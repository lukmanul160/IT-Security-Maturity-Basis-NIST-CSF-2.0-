# Progres upload aplikasi

Semua fetch multipart menuju API aplikasi dengan berkas FormData menggunakan transport XMLHttpRequest bersama (`services/uploadProgress.js`). Persentase dihitung dari byte yang benar-benar dikirim oleh browser, termasuk envelope multipart. Setelah unggahan selesai, bar berubah menjadi indeterminate selama server melakukan validasi/penyimpanan; 100% selesai baru ditampilkan setelah respons berhasil diterima. HTTP error, jaringan terputus dan pembatalan ditampilkan sebagai gagal, bukan selesai.

Transport mempertahankan method, header, AbortSignal, respons/status HTTP, dan kredensial same-origin. Fetch JSON biasa, Request object, URL eksternal dan credentials omit tetap memakai fetch asli. API dan izin backend tetap berlaku. Permintaan paralel mempunyai kartu progres terpisah. Nama dan ukuran setiap file ditampilkan sebagai teks, dengan daftar yang dapat digulir. Kartu aktif ditampilkan dalam dialog yang terbuka atau area halaman, dengan tampilan terang/gelap, ukuran mobile dan reduced motion.

Cakupan multipart: Uploaded Files, unggah/penggantian evidence CSF/Privacy/ISO, evidence gap, dokumen vendor TPRM, Policy Register, Audit Finding, foto aset/rak dan import Asset Management, gambar/impor Knowledge Notes, File Backup batch restore, dan Database Backup restore. Impor JSON modul serta assessment yang dibaca di browser mempunyai indikator baca/validasi dan progres jumlah record tersimpan. Impor Knowledge Notes memakai kartu yang sama dari membaca file sampai upload dan pembaruan daftar.

File Backup dan Database Backup mempunyai panel progres pada halaman masing-masing. Pembuatan backup di server dan proses database restore menggunakan bar indeterminate karena endpoint tidak menyediakan persentase pekerjaan server. Panel restore menampilkan persentase upload dahulu, kemudian fase server. Pemilihan ZIP batch menampilkan semua nama/ukuran ZIP; setelah restore, daftar tetap terlihat dengan status Dipulihkan. Database restore mengakhiri sesi sesuai perilaku backend; tombol Login kembali muncul setelah hasil berhasil diterima, tanpa permintaan refresh daftar yang dapat salah melaporkan keberhasilan sebagai error sesi.

Validasi: `npm run test:uploads`, suite transfer/backup, dan `npm run test:file-backup-browser`. Browser fixture memeriksa semua rute multipart, progress 35/50/60%, fase server, error, konkurensi, dialog, database backup/restore, filename, dark/mobile, serta satu unggahan native nyata ke endpoint lokal terisolasi. Pengujian restore database menggunakan respons fixture; database aplikasi tidak dipulihkan selama pengujian UI.
