# IT Governance Monitoring Dashboard

The shared dashboard summarizes every existing readable module without adding a second business registry. Seven groups cover frameworks/assessments/compliance/policies, risk/acceptance/audit/threat modelling, assets/racks/relations, TPRM, personnel/certifications, knowledge/evidence, and administration. Admin-only account, audit-event, backup, SMTP and storage summaries remain restricted to administrators.

Eight clickable KPIs show available sources, overdue records, deadlines within 30 calendar days, unavailable sources, high/critical/at-risk indicators, pending work, incomplete data, and process references. Search, group and priority filters apply consistently to KPIs, group coverage, the six-month new-record chart, the module summaries, attention queue and JSON export. Group coverage charts compare module availability, not incomparable business-record totals. The attention queue contains only module-level summaries and has eight items per page.

Indicators retain module meanings. Closed risks and closed findings do not contribute overdue/high-active counts. Retired/disposed assets do not contribute active CIA/renewal counts. Asset CIA levels derive from the four stored indicators. Acceptance status requires all three name/signature/date stages and valid decisions; its due date is remediation, not approval expiry. Accepted/mitigated threats are excluded from open threats. Failed audit events are tracked as operational attention, separate from pending governance work. Active TPRM vendors and unfinished questionnaires are monitored separately. Policy review dates use the existing month-clamped schedule; Ad hoc has no periodic deadline. ISO objectives count At risk across their saved evaluation periods. Configuration presence does not imply successful SMTP delivery or live infrastructure health.

Indicators may overlap within or between modules. The interface explicitly states that their sum is not a unique record count. Missing permissions remove a source entirely; a failed authorized source is displayed as unavailable instead of zero. JSON export contains aggregates only and preserves the current filter scope. It contains no names/signatures from acceptance requests or SMTP secrets.

Verification: `npm.cmd run build:client`, `npm.cmd test`, `npm.cmd run test:monitoring-browser`, and `npm.cmd run test:monitoring-workspace`. Synthetic browser checks cover scope intersections, issue KPIs, eight-item pagination/reset, filtered export, empty/unavailable states, and desktop/mobile layouts. The workspace check uses real read-only APIs and verifies all permitted module sources and navigation.
